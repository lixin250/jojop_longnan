# 存档白名单与同步策略（IAA）

面向 JojoP 这类 **IAA 超休闲**：客户端是权威玩法，Cloudflare 只存「配置 + 可接受丢失/可覆盖」的数据。  
目标不是「银行级必达」，而是 **本地优先 + 可重试 + 最终大致一致**。

> **纯看广告（IAA）**：不用接充值/内购订单，也不用自建支付账本。  
> 广告相关做好即可（AdMob、激励/插屏、频控、隐私同意）。  
> 下面「禁止存可提现余额/内购订单」是防以后误加；当前 IAA 直接忽略即可。

---

## 1. 允许存什么（白名单）

### A. 远程配置（全员一份，不跟玩家走）

| 字段例子 | 说明 |
|----------|------|
| `adsEnabled` / `rewardedEnabled` / `interstitialEnabled` | 广告总开关 |
| `dailyRewardedCap` | 每日激励上限 |
| `interstitialEveryNRetries` | 插屏节奏 |
| `eventId` / `eventEnabled` | 今日活动是否开（只是开关，不是发奖账本） |

**拉取时机：** App 启动、进主界面前；也可定时（如每 10 分钟）或切前台再拉一次。

### B. 玩家轻量档案（按 deviceId / 以后 userId）

| 字段例子 | 适合？ | 说明 |
|----------|--------|------|
| `settings`（音量、震动、语言） | 适合 | 丢了可再设 |
| `meta`（体力/培养点/章节解锁） | 适合 | 局外养成，可被刷，别当真钱 |
| `tutorialDone` | 适合 | 布尔标记 |
| `lastLoginDate` / `loginStreak` | 谨慎 | 可做；别和「真发钱」绑定 |
| `daily.eventId` + `daily.joined` / `daily.claimed` | 谨慎 | **只做展示/软限制**；真正发奖要防刷 |
| `bag` 小背包（皮肤解锁 bool、道具数量） | 看量 | **无付费、可补发** 才适合 KV；数量别当钱 |
| 广告「可提现余额」、内购订单 | **禁止** | 走 AdMob/IAP + 正经库 |
| 实时对战状态、帧同步 | **禁止** | 不走这套存档 |

**原则：** 丢了、被改了，不能导致你亏真钱或客服炸锅，才能进 Cloudflare KV。

---

## 2. 什么时候「拉」（Read）

推荐顺序（启动流水线）：

```text
1. 本地先读缓存（秒开）
2. 隐私同意（若需要）
3. GET /config          ← 全员配置
4. 初始化广告 SDK
5. GET /save/:id        ← 玩家档（有则合并到本地）
6. 进游戏 / 主界面
```

### 合并规则（很重要）

- **设置类：** 远端优先，或「谁时间戳新听谁」  
- **养成进度：** `max(本地, 远端)` 或「谁时间戳新听谁」  
- **教程标记：** `本地 || 远端`（有一边完成就算完成）  
- **日活动：** 以 `eventId` 对齐；活动换天则本地日进度重置  
- **背包数量：** IAA 无商城时可用「取较大值」；一有付费就别这么干

**失败怎么办：** 拉失败 → **继续用本地缓存开玩**，后台静默重试。不要卡死在登录转圈。

---

## 3. 什么时候「存」（Write / 推送）

| 触发点 | 存什么 | 优先级 |
|--------|--------|--------|
| 改设置（音量等） | `settings` | 可防抖 1～2 秒再存 |
| 结束一局 / 养成变化 | `meta` | 排队 |
| 参与/领日活动（软） | `daily.*` | 立刻排队 |
| 背包变化（解锁皮肤等） | `bag` | 立刻排队 |
| 切后台 / 即将暂停 | 刷出队列里所有待存 | 高 |
| 断线重连成功 | 再刷一次队列 | 高 |
| 定时（如每 60 秒） | 若有 dirty | 低 |

**不要：** 每一帧、每一次普攻都 PUT（费流量、易打架）。

---

## 4. 「一定成功」做得到吗？

### 短答案：**做不到 100%，也不该承诺 100%。**

网络会断、进程会被杀、KV 会限流、手机没电。  
能做到的是：**绝大多数情况成功；失败可恢复；最坏损失可接受。**

### 实际可靠做法（建议你们就按这个）

1. **本地权威草稿（Local-first）**  
   - 所有变更先写 `PlayerPrefs` / 本地 JSON，并标 `dirty=true`  
   - 再异步 `PUT /save`  
   - 成功后清 dirty / 记 `serverRev`

2. **发送队列 + 重试**  
   - 失败：指数退避（1s、2s、4s…上限 60s）  
   - App 重启：若 dirty，启动后再发  
   - 只保留「最新一份整档」覆盖写即可（IAA 够用），少搞多版本合并地狱

3. **整档覆盖，而不是碎字段狂写**  
   - 每次 PUT 一整份小 JSON（建议 &lt; 8KB，你们 Worker 已有大小限制）  
   - 避免「只写 bag、没写 score」导致半新半旧

4. **断线 / 切后台**  
   - `OnApplicationPause(true)` / `OnApplicationQuit`：尽量同步踢一脚保存  
   - **注意：** 移动端杀进程不保证 Quit 跑完 → 所以平时就要 dirty+队列，不能只靠退出那一下

5. **读取**  
   - 启动：本地先显示，远端回来再合并  
   - 超时（如 3～5 秒）就别等了，进游戏

6. **什么叫「成功」**  
   - 客户端收到 HTTP 2xx +（可选）返回 `rev`  
   - 没收到 ACK → 当作失败，保持 dirty，下次再发  
   - **不要**假设「发出去了就一定写进 KV」

### 做不到 / 别强求的

| 诉求 | 现实 |
|------|------|
| 杀进程瞬间 100% 云端已写入 | 不可能保证 |
| 弱网下每次打开都和服务器字节级一致 | 成本高，IAA 不值 |
| 防所有作弊改分/改背包 | 客户端可改；无服务端权威就只能防君子 |
| 日活动发「真货币/真可交易物」且绝对公正 | 需要强校验后端，不是 KV 存档能搞定 |

## 5. 和「登录」的关系（以后扩展）

现在：`deviceId` 即可。  

以后若要 Google 登录：

```text
游客档(deviceId)  --绑定-->  userId 档
合并：分数取 max，设置取新，背包按规则合并
```

拉取时机仍是：**进可玩状态前拉一次配置 + 拉一次档案**；不是每局都全量拉。

## 6. JojoP 建议的最小 JSON 形状

```json
{
  "rev": 3,
  "updatedAt": 1730000000,
  "settings": { "bgm": 1, "sfx": 1, "vibrate": true },
  "progress": { "best": 12, "totalPlays": 40, "tutorialDone": true },
  "daily": { "eventId": "2026-07-31", "joined": true, "claimed": false },
  "bag": { "skin_default": 1, "skin_alt": 0 }
}
```

- `rev`：本地每次改 +1；可选，方便以后打日志  
- 日活动只存标记；**发奖内容以 `/config` 的 event 为准**

---

## 7. 一句话纪律

- **拉：** 启动用缓存开路，远端合并，失败不堵玩  
- **存：** 先本地 dirty，再排队 PUT；切后台刷队列  
- **成功：** 只有 ACK 才算；否则重试  
- **100%：** 不承诺；把「丢档」设计成可接受（IAA 本来就该这样）
